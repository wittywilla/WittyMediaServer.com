Start here#

Settings → Repair checks the database, metadata, modules and this install. It says what it found in plain words, and fixes what can be fixed, with a safety copy first. Your media files are never changed. See Repair.

If you can’t open the app, the same thing works on the computer running the server:

wittymediaserver doctor         # looks, and changes nothing
wittymediaserver doctor --fix   # fixes what it can

Settings → WittyLog shows what the server recorded, and explains common failures in plain words. See Getting help.

Connecting#

What you’re seeingWhat to do
Other devices at home can’t open the serverUse the computer’s network address, not localhost. Settings → About shows it. Check that the firewall on that computer allows port 9797. On Windows, the network has to be marked Private for the installer’s firewall rule to apply
It says the server only accepts connections from this computerThe server is set to listen only on this computer. Set listen to :9797 in its config file, then restart it
An app doesn’t list the serverApps find it over UDP ports 5353 and 9797, which a firewall may block. Wi-Fi with client isolation or a guest network keeps devices apart, and a container needs host networking. Check Settings → Profiles → Signing in → Let apps find this server. Typing the server’s address in the app always works. See Apps and devices
It doesn’t work away from homeThat’s expected until you turn on Settings → Remote Access. See Remote access, which has its own troubleshooting
”This server is only available on its home network.”Settings → Remote Access is set to Home network only, and the server sees you as outside. Choose a way in from a device at home. Behind a reverse proxy, also list the proxy as trusted: see Remote access
An app warns that this isn’t the server you used beforeCompare the fingerprint with the one on your server’s Sign in a TV page. See Apps and devices

Setting up and signing in#

What you’re seeingWhat to do
Setup asks for a setup codeYou’re setting up from another device. The code is on the server’s console, in docker logs wittymediaserver, in journalctl -u wittymediaserver, or in setup-code.txt in its data folder. It changes each time the server starts. See Setting up from another device
”Too many wrong setup codes.” or ”Too many wrong tries.”Wait, then try again. The second message says how long
You forgot your passwordSee If you forget your password
You lost your phone and can’t get a sign-in codeEnter a recovery code in its place. If those are gone too, see Two-factor sign-in
A profile with no password won’t sign inThese work only on your home network, and only with the Profiles sign-in screen. See Signing in
A native app won’t sign in to an account with two-factorThose apps don’t ask for the code yet. Use Sign in with a code
Part of Settings is missingPages about the server are for administrators. See Who can do what
Someone can’t see a library or a titleCheck their Limits under Settings → Profiles. A title with no rating stays hidden under an age limit unless you allow it. See Hiding things, and who sees what

Libraries and scanning#

What you’re seeingWhat to do
New files don’t appearThe server scans every 6 hours, and doesn’t watch folders as they change. Press Scan now under Settings → Libraries
”folder not found”The server has to be able to see the folder, and it may run as a different account from you. A Windows service runs as LOCAL SERVICE, and a Linux service as wms: give that account permission to read it. In Docker, use the path inside the container, such as /media/movies
”That path is on another machine”Network shares can’t be added from another device, unless you allow it. See Network shares
A scan finds nothing, or misses filesThe activity button lists folders it had trouble with. Check the file types in Supported formats. Film and TV libraries skip folders named extras, files starting with sample, and videos under 5 MB. See How to lay out and name your files
A kind of library is under “Add a module to use these”It needs a module this server doesn’t have. Press the button beside it. See Modules and the store
Everything from one drive is still listed while it’s awayThat’s on purpose. A folder that’s empty or can’t be reached keeps its titles until it’s back, because an unplugged drive looks like an empty folder. Files really deleted from a folder that’s there leave at the next scan
You moved a drive, and everything’s gone from the libraryUse Settings → Repair → Moved a drive?, or wittymediaserver doctor remap --from <old> --to <new> --fix. Watch progress, matches and your edits stay. See Moved a drive?

Titles and posters#

What you’re seeingWhat to do
A title is named strangelyRename the file to Title (Year).ext, or press Edit on its page
A title has the wrong detailsPress Edit on its page and use Search and match, or go through Fix matches on the library’s page. See Metadata
Lots of titles have wrong details, or an NFO is brokenSettings → Repair → Metadata files lets you fix them in a text editor, with what would change shown first, and problems named by file and line. With the server stopped, wittymediaserver metadata check does the same. See The metadata folder
Posters are missingAdd a free TMDB key, or a custom agent, under Settings → Metadata agents, then press Refresh on the title

Playing video#

Start with If it won’t play for anything to do with the player itself.

What you’re seeingWhat to do
”ffmpeg not found”Keep the program’s bin folder as it was installed, install FFmpeg on your PATH, or set WMS_FFMPEG. Settings → About shows which one is in use
Video stalls, or has no sound, in one browserSome Linux builds of Chromium can’t play AAC. Set Settings → Live transcoding → Sound format while converting to MP3
”this server is busy with other streams”As many videos are converting as maxTranscodes allows, all with someone watching. Raise it in the config file if the machine can take it
Video stalls, or a folder or drive misbehavesSettings → WittyDiagnoser → Storage checks free space, permissions, read speed and known trouble. See WittyDiagnoser

Discs#

What you’re seeingWhat to do
”This disc is encrypted, so it can’t be played”The image is copy protected. Encrypted media isn’t supported, and nothing here bypasses copy protection
A disc won’t play, stutters or stops partwaySettings → WittyDiagnoser says what’s wrong with a copy: scrambled, incomplete, or with sectors that can’t be read
A DVD or Blu-ray menu shows no buttonsCheck the disc in Settings → WittyDiagnoser with Press every menu button on. Its report says which buttons lead nowhere. Share the report, never the disc image
A disc’s page has no way to play itPlaying a disc takes a disc module. See Modules and the store

Modules#

What you’re seeingWhat to do
A page says its module is missingAn administrator can add it from there, or under Settings → Modules
A module won’t install or updateThe error says what happened and what to try, and Show details has more. See When something goes wrong
A module won’t load after an updateUse Settings → Repair, or wittymediaserver doctor --only modules. To download it again, use wittymediaserver doctor reinstall <module>. See A module is broken

Games#

What you’re seeingWhat to do
A game takes a long time to start the first timeOn Windows, a security scanner may hold a new program the first time it runs, for up to about half a minute. It’s quick after that
A PSP game is slow to start the first timeThe PSP core sets up its own files in that game’s save folder, about 20 MB, once per account for each game
A game is refused as encryptedSee Encrypted games

Games covers saves, controllers and streaming.

If it won’t start#

What you’re seeingWhat to do
The server won’t startRun wittymediaserver doctor on that computer. It works when nothing else does, and says why: a damaged database, a mistake in wms.json, FFmpeg missing, the port taken. wittymediaserver doctor --fix repairs what can be repaired
”WittyMediaServer is already running”It is: a second start of the same data folder doesn’t start a second server on it. Open WittyMediaServer opens the one that’s running. Start another server… starts a separate one, with a data folder and port of its own (its own libraries, accounts and settings), never the same folder: two servers on one database would damage it
wittymediaserver says it’s already running and exits with code 3A start without a desktop (a service, Docker, a terminal, a script) prints where the running server is and exits with code 3, instead of asking. The service files don’t restart on that code. If it says the server is starting or not answering, wait a moment and try again; if it never answers, end it (Task Manager, kill) and start again. A server that crashed or was ended leaves nothing behind that blocks the next start
The server says port 9797 is in useIt names what has it: another WittyMediaServer with a data folder of its own (the installed service, or a second server), or another program. Stop that, or give the server another port in Settings → Network, or with port in settings.ini beside the program. The message suggests a free one
Nothing opens after changing the portOpen the new address, http://<this computer>:<new port>: bookmarks still have the old one. Still nothing? A firewall of your own, other than Windows’ rule from the installer, needs the new port. To go back, set port = 9797 in settings.ini and restart the server. wittymediaserver config port says which file it reads
Settings → Network says the port is set somewhere else-listen, WMS_LISTEN or listen in wms.json win over Settings, and the page says which and where. Remove it to choose the port in Settings. In Docker, change the published port in docker-compose.yml instead
A line of settings.ini was skippedThe page and the log name the file and line. A port is a number from 1 to 65535, written port = 8096. Everything else on that line after # is a note
An app can’t find the server after the port changedApps that find it on the home network catch up by themselves. One set up by typing an address needs the new port: 192.168.1.20:8096
Windows blocks the installer or the programAlpha builds aren’t code-signed yet. If SmartScreen says “Windows protected your PC”, choose More info, then Run anyway. If Smart App Control blocks it, see Smart App Control on Windows

Smart App Control on Windows#

Smart App Control is part of Windows 11’s security: when it’s on, Windows runs only programs and libraries that are signed by a publisher it trusts, or that Microsoft already knows. There’s no way to allow one program, and once it’s turned off, Windows can’t turn it on again without being reinstalled. So we never ask you to turn it off, and you shouldn’t need to.

WittyMediaServer’s programs aren’t signed yet, so today Windows blocks them, the installer included, on a PC where it’s on. Signed releases are being prepared. Settings → About → This server says whether it’s on, and so does the diagnoser.

What you’re seeingWhat it means
”Smart App Control is on, and … isn’t signed by a publisher Windows trusts”, installing a moduleNothing was installed. WittyMediaServer’s own modules will come signed. For a module from another store, ask its publisher for a signed build
”Smart App Control blocked …”, starting a moduleWindows refused the module’s program. Install a signed version when there is one
”… in this core isn’t signed”, installing a game coreGame cores come unsigned from libretro’s build server, so games can’t start on this PC yet. Signed cores are planned
Smart App Control is in evaluationWindows is watching which programs run, and will turn it on or off by itself. It blocks nothing yet

To see whether a file is signed: right-click it in File Explorer, choose Properties, and look for a Digital Signatures tab. If it isn’t there, the file isn’t signed.

Starting again#

What you wantWhat to do
A copy of everything before something riskySettings → Backup makes one ZIP of your data and metadata, and first-time setup can bring it back. On the command line, use wittymediaserver backup create and wittymediaserver backup restore. See Backup and restore
To start again from a new installSettings → Reset puts the server back as it was first installed, with warnings first, and asks for your password. It keeps a copy you can bring back, unless you choose to delete everything. Your media files are never touched
To reset when you’re locked out, or the server won’t startRun wittymediaserver reset on the server, then start it. wittymediaserver reset -list and -restore <copy> work with the copies, and -cancel takes back a reset that’s waiting

Other questions#

QuestionAnswer
Where is my data?Settings → About shows the data folder, and so does wittymediaserver config path. wms.db there is the database, cache/images the artwork, and transcode is temporary. See Config file
Can I use an LGPL-only FFmpeg?Yes, nothing requires GPL parts. Set WMS_FFMPEG to an LGPL build with libopenh264 or a hardware encoder

Getting help#

  1. Make the problem happen again.
  2. Go to Settings → WittyLog and press Download logs as ZIP, on any tab of that page.
  3. Leave Sanitize for sharing on. Names, addresses, paths and titles become placeholders, and you can see what it holds first. Passwords, tokens and API keys are taken out of every copy.
  4. Pass that file to whoever is helping you. Nothing is ever uploaded by the server.

If the server won’t start, wittymediaserver logs zip makes the same file without it. For anything to do with discs or drives, also run Settings → WittyDiagnoser, and share its report. Never share a disc image.
