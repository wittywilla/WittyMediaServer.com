Config file and folders

Set what the server has to know before it starts: its port, where it keeps its data, and a few security switches that a web page can’t change.

Changed 2 November 2026 Edit on GitHub

Everyday settings are in Settings, and you never need a config file. Without one the server uses its defaults.

Where the config file goes#

The file is called wms.json. The server uses the first one it finds:

OrderWhereWhen to use it
1The file named by -config <file> or WMS_CONFIGServices, scripts, several servers on one machine
2In the program’s top folder, beside WittyMediaServer.exe and binPortable mode
3Your own config folder, listed belowA normal install
4FreeBSD only: /usr/local/etc/wittymediaserver/wms.jsonSystem services
5Linux and BSD: /etc/wittymediaserver/wms.jsonSystem services

Your own config folder is:

SystemFile
Windows%APPDATA%\WittyMediaServer\wms.json
macOS~/Library/Application Support/WittyMediaServer/wms.json
Linux, BSD~/.config/wittymediaserver/wms.json, or under $XDG_CONFIG_HOME if that’s set

To write a starter file, and to see which file and folders are in use:

wittymediaserver config init
wittymediaserver config path

A wrong name in the file stops the server with a clear message, instead of being ignored. wittymediaserver doctor works even then: see Repair.

A service with a config file. On Linux use /etc/wittymediaserver/wms.json, and on FreeBSD /usr/local/etc/wittymediaserver/wms.json. On a Mac the service runs as you, so it uses your own. On Windows, put it in C:\Program Files\WittyMediaServer.

Packaged services and the image set two things themselves. The Linux, FreeBSD and Mac services set WMS_DATA_DIR and WMS_LISTEN, the Windows service passes -data and -listen, and the Docker image also sets WMS_TRANSCODE_DIR. These win over the file, so listen and dataDir in a config file do nothing there. See Installing for how to change them on each system.

What you can set#

Every setting is optional. Most can be given three ways, and the strongest wins: a flag, then a variable, then the file. Flags go after wittymediaserver serve.

In wms.jsonFlagVariableWhat it does, and its default
listen-listenWMS_LISTENThe address and port. :9797, the default, is every network card on port 9797. 127.0.0.1:9797 keeps it to this computer
dataDir-dataWMS_DATA_DIRThe server’s own folder: database, settings, users, watch history. Default: see below
metadataDirWMS_METADATA_DIRDownloaded posters, backdrops and generated thumbnails. Default: images in the cache folder
cacheDirWMS_CACHE_DIROther cached files, such as disc playlists and menu stills. It stays within limits: 4 GB of thumbnails, 1 GB of stills, 4 GB of unpacked comics, oldest first, and what’s removed is made again when it’s needed. Default: cache in the data folder
transcodeDirWMS_TRANSCODE_DIRTemporary video while transcoding. Put it on a fast SSD or RAM disk. Default: transcode in the data folder
logDir-log-dirWMS_LOG_DIRLog files. It can also be changed in Settings → WittyLog. Default: logs in the data folder
logLevel-logWMS_LOGerror, warn, info (the default) or debug. debug makes every area of the log as detailed as it goes, whatever Settings → WittyLog says
ffmpeg, ffprobe-ffmpeg, -ffprobeWMS_FFMPEG, WMS_FFPROBEUse these FFmpeg programs. Default: the ones in bin, then PATH
maxTranscodes-max-transcodesWMS_MAX_TRANSCODESHow many videos may be transcoded at once. Lower it on small machines. When all are in use, a stream nobody has asked anything of for 20 seconds gives way, otherwise the next viewer waits. Default: 4
maxConnections-max-connectionsWMS_MAX_CONNECTIONSHow many connections can be open at once, for the whole server. One address (an IPv6 network counts as one) can hold 128 of them, except this computer and trusted reverse proxies, and 64 more are kept for the home network. At least 16. Default: 2048
publicUrl-public-urlWMS_PUBLIC_URLThe address people use from outside your home, such as https://media.example.com. Setting it also turns remote access on
openBrowser-open-browser=falseWMS_NO_BROWSER=1Whether to open the setup page in your browser the first time the server starts. Default: yes
portableKeep everything next to the program. Default: false. See Portable mode

These are in Security switches:

In wms.jsonFlagVariable
setupFromHome-setup-from-homeWMS_SETUP_FROM_HOME=1
allowNetworkPaths-allow-network-pathsWMS_ALLOW_NETWORK_PATHS=1
remoteAccess-remote-accessWMS_REMOTE_ACCESS=1
trustedProxies-trusted-proxiesWMS_TRUSTED_PROXIES
javaPath-javaWMS_JAVA
gamingCustomCores-gaming-custom-coresWMS_GAMING_CUSTOM_CORES=1

Each is off, or empty, until you set it. A switch that’s on in the file can’t be turned off by a variable: remove it from the file.

Paths. A relative path, like "data", is relative to the folder the config file is in.

An example:

{
  "listen": ":9797",
  "dataDir": "D:\\WittyMedia\\data",
  "metadataDir": "E:\\Artwork",
  "transcodeDir": "R:\\transcode",
  "logLevel": "info",
  "maxTranscodes": 4
}

Security switches#

These are here, and not in Settings, on purpose. Each one changes what someone with a web session can do or reach, so it’s set on the machine, by whoever runs it.

NameWhat it doesWhy it’s off
setupFromHomeLets anyone on the home network make the first account without the setup codeWhoever makes the first account owns the server. Off, only the server’s own desktop goes without the code
allowNetworkPathsLets settings changed from another device name a network share, such as \\nas\media, or a device pathReaching a share signs in there with the server’s own account, on Windows the machine’s. Without it, choose a share on the server’s own desktop, or use a mapped drive or a mount. Libraries already on a share go on working
remoteAccessAllows connections from outside your home without using Settings → Remote Access, for a server nobody can reach from a home network first, such as a rented one. It also locks the switch on that page. See Remote accessNothing answers from outside until you ask for it
trustedProxiesReverse proxies whose X-Forwarded-For is believed: addresses or networks, separated by commas. These are added to the ones in Settings → Remote AccessAnyone else could claim to be at home
javaPathThe Java folder, or the java program in it, for Blu-ray menus. The server looks for it by itself if this is empty. See Blu-rayA web account can’t choose what the server runs. A location saved in Settings by an older version is ignored
gamingCustomCoresLets custom game cores be turned on in Settings → Consoles & cores. See Your own coreA core is a program, and can read what the server can

Three more are variables only, with no setting and no flag, so a web session and the config file have no say:

VariableWhat it does
WMS_NO_MODULE_FORKS=1Keeps modules from other publishers off, whatever an administrator asks, and makes the server forget one already chosen. See Using someone’s fork
WMS_GAMING_NO_CUSTOM_CORES=1Keeps custom game cores off, whatever else is set
WMS_TUNER_COMMANDS=1Allows the custom command tuner, which runs a program on the server

Variables with no setting#

VariableWhat it does
WMS_CONFIGThe config file to use, the same as -config
WMS_BACKUP_PASSWORDThe password for wittymediaserver backup, as a password is never taken on the command line. See Backup
WMS_DOCKER=1Says this is a container, so the server doesn’t try to replace its own files. The image sets it
XDG_DATA_HOME, XDG_CONFIG_HOMEOn Linux and BSD, the system’s own settings for where a person’s data and config folders are

Setting a variable for a service#

Where there’s a setting in wms.json, that’s the simplest way. For a variable with none:

How it runsWhat to do
The tray appSet it in your account’s environment, then choose Quit and open the app again
Linux servicesudo systemctl edit wittymediaserver, add [Service] and Environment=WMS_NO_MODULE_FORKS=1, save, then sudo systemctl restart wittymediaserver
FreeBSD servicesysrc wittymediaserver_env="WMS_NO_MODULE_FORKS=1", then service wittymediaserver restart
Windows serviceAs an administrator: reg add HKLM\SYSTEM\CurrentControlSet\Services\WittyMediaServer /v Environment /t REG_MULTI_SZ /d WMS_NO_MODULE_FORKS=1, then sc.exe stop WittyMediaServer and sc.exe start WittyMediaServer
Mac serviceAdd it under EnvironmentVariables in /Library/LaunchDaemons/com.wittywilla.wittymediaserver.plist, then sudo launchctl bootout system <that file> and sudo launchctl bootstrap system <that file>. A new .pkg writes this file again, keeping only the data folder and port, so add it again after updating
DockerUnder environment: in the compose file, or -e with docker run

Portable mode#

Portable mode keeps everything in one folder: program, database, artwork and logs. You can run the server from a USB drive or an external disk, or keep several separate copies.

To make an unpacked folder portable, put a wms.json in its top folder, beside bin:

{ "portable": true }

Or run wittymediaserver config init --portable. Any wms.json in that folder makes a copy portable, whatever it says. The data then lives in a data folder beside the program.

Keep a portable server on a drive that stays plugged in while it runs. Back up the whole folder to keep your libraries, users and watch history.

Folders the server uses#

Without a config file the data folder is:

How it runsData folder
Windows, in your account%LOCALAPPDATA%\WittyMediaServer
Windows, as the serviceC:\ProgramData\WittyMediaServer
macOS~/Library/Application Support/WittyMediaServer
Linux or BSD, in your account~/.local/share/wittymediaserver, or under $XDG_DATA_HOME if that’s set
The Linux package’s service/var/lib/wittymediaserver
The FreeBSD package’s service/var/db/wittymediaserver
Docker/config

The command line uses the same rules, so run it as the same account, or say which folder:

  • As root, on a .deb, .rpm or FreeBSD package, it uses the service’s folder.
  • With a copy from install.sh, add -data /var/lib/wittymediaserver.
  • For the Windows service, add -data C:\ProgramData\WittyMediaServer, in a terminal opened with Run as administrator.

Inside the data folder:

  • wms.db is the database. cache/images holds the artwork, and transcode is temporary.
  • backups holds the backups you make, and the safety copies from restores and repairs. A reset that keeps a copy leaves it where it is.
  • metadata holds one plain text file for each title, to fix by hand. It’s filled when you export it, and nothing reads it until you apply it. See The metadata folder. It isn’t the same as metadataDir, the artwork folder.
  • Uninstalling lists every name.

To move the artwork folder:

  1. Stop the server.
  2. Move the folder’s contents to the new place.
  3. Set metadataDir.
  4. Start the server.

Artwork is referenced by file name, so nothing has to be scanned again. The same works for transcodeDir, which only holds temporary files.

Logs#

Logs are plain text files named wms-<date>.log, one line per message, in the log folder. A new file starts after 20 MB. They’re kept for 14 days and 200 MB in all, whichever comes first. If the disk has under 100 MB free, only warnings and errors are written and old logs are removed. If the folder can’t be written, the log stays in memory and the settings page says so.

Logs never leave your server. Nothing is uploaded, and nobody sees them unless you send a file yourself. Passwords, sign-in tokens, stream tokens, API keys, PINs, cookies and setup codes are removed from every line.

Settings → WittyLog has a live viewer with explanations in plain words, a level for each area and module, Catch a problem, Crash reports, and Download logs as ZIP with Sanitize for sharing. See Logs.

With no server running, for a server that won’t start:

wittymediaserver logs zip [-data <dir>] [-o out.zip] [-days N] [--raw]
wittymediaserver logs sanitize [-data <dir>] [-o out.txt] <file>

The first makes a ZIP, sanitized unless you add --raw. The second makes a sanitized copy of any text log. They only read. The database is looked at for the names to hide. If it’s too broken to read they say so and carry on, replacing everything that looks like a name, address or path.

For developers#

Variable or flagWhat it does
-dev, WMS_DEV=1Serves web/dist from disk instead of the built-in copy
-watch-stdin, WMS_WATCH_STDIN=1Exits when stdin closes. The tray app uses it
WMS_RESTARTED=1Set by the server for the copy it starts after an update, so that it keeps trying the port
WMS_WITTYPLAY_RUNNERRuns games with this program, in place of what the module brought
WMS_WITTYCOUCH_HOSTUses this program as the WittyCouch host
WMS_GAMING_TESTCORE=1Offers the built-in test console

Only a build with the updatetest tag reads WMS_UPDATE_FEED, WMS_UPDATE_KEY, WMS_MODULE_FEED and WMS_MODULE_CATALOG.

Build scripts read WMS_SIGNING_KEY, WMS_STARTER, WMS_PREBUILT, WMS_MODULE_REPOS and WMS_FORBIDDEN_NAMES. The rest are for tests, and do nothing in a running server: WMS_TEST_*, WMS_REAL_*, WMS_FORMAT_*, WMS_MOCK_*, WMS_SANDBOX_*, WMS_CRASH_*, WMS_GAME_*, WMS_GAMES_FOLDER, WMS_HOSTILE_FULL, WMS_LOG_TEST_EXIT, WMS_TDARR_*, WMS_UPDATE_OPENAPI, WMS_NAME, WMS_PASS, WMS_SERVER and WMS_TMP.
