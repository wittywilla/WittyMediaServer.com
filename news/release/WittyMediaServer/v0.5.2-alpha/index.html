WittyMediaServer 0.5.2-alpha

Release notes

Article

Games, live TV and a full audit

Console games streamed from your server, channels made from your library, live TV, photos, remote access, and the fixes from a full code and design audit.

Read it

[!WARNING] This is an alpha release. Expect bugs, and expect settings and APIs to change between versions. It hasn’t had an independent security audit. Keep backups of anything you care about, and read the remote access guide before making your server reachable from outside your home. The software comes with no warranty: you run it, so what you host and who you let in are your responsibility.

0.5.0-alpha was never published, so this is the first public release with everything since 0.4.0-alpha.

What’s new

  • Games: console games streamed to your browser, with GPU cores, games inside archives, controller profiles with a picture-based mapper, display effects and overlays, core options, game details and ratings from several sources, and your own custom cores. You supply your own games and BIOS files, legally obtained.
  • Game PCs: play on any PC running Sunshine, in your browser, with WittyCouch. WittyRigs is an advanced option for hosting demanding games on the server itself.
  • Audio CDs: WittyCD plays CD images in an on-screen CD player, with the WittyVisualizer plugin for music.
  • Internet radio: search a directory of stations, with logos, details and what’s playing now.
  • Modules: a new Modules page, with versions you can choose and updates that don’t need a new server.
  • WittyLog and WittyDiagnoser: logging that captures problems across everything, and a disk and disc checker with no command line.
  • DVD and Blu-ray: chapter changes no longer skip, and playlist items join on their exact frames.
  • Settings → Reset: start again from a new install, with a copy kept that you can bring back. Your media files aren’t touched.
  • A Legal page, with notices across the app.

This release also has the fixes from a full code and design audit, covering security, crashes, lost saves, phone layouts and error messages. The changelog has the details.

Known limits

  • Encrypted DVDs, Blu-rays, broadcasts and games are refused, and nothing here decrypts them.
  • Game PC streaming has been tested against a real Sunshine, but not yet on a real gaming PC with a real game.
  • Blu-ray Java menus are off by default, and haven’t been proven on retail discs.
  • The Docker image is about 800 MB, because game cores need Debian rather than Alpine.

WittyMediaServer is an independent open-source project under the Apache License 2.0. Third-party components keep their own licenses, listed in Settings → About.

Everything in this version

0.5.0-alpha was never published as a release, so this is the first release with everything from it as well (see its section below). This one adds the fixes from a full code and design audit, Settings → Reset, and a remote access guide written around security.

  • Fixed: on Linux, an installed module could fail to start on a busy machine and be counted against its version: its address space limit was too close to what Go sets aside when it starts. Real memory use stays limited as before.
  • Server 0.5.2-alpha: The code and design audits: security and reliability fixes across the server, games, discs, modules, apps and the web UI, and a remote access guide written as a security guide.
  • Modules: a withdrawn version can’t be missed: the list is read on every check, not only when the list of releases changes. A file uploaded again is noticed by its upload time.
  • Fixed: a normal install and the Mac app left out the game runner, so games couldn’t start.
  • Security: the helper sandbox refuses x32 system calls and io_uring, which got around its limits on sockets. Signing checks a release’s file names exactly, so another version can’t pass as this one, and more kinds of password and key are hidden in logs.
  • Fixed: a server stopped by a power cut in a container now reports it, even with the same process number each time. A restart now brings a container back on any container runtime.
  • Containers: :latest moves only for full releases, and :alpha is the newest alpha. docker-compose.yml follows :alpha.
  • Scripts: the cutover stops if moduleKey isn’t the key given, or if something it removes wouldn’t be available afterwards, such as WittyCouch Host’s source. mirror.sh refuses to push workflows naming an unpublished tool version. ScreenScraper’s developer id is described as what it is: not built in today.
  • Privacy: collections, recent games and CD pages no longer show non-admins where files are on the server, and an HLS radio station’s address no longer reaches listeners or the logs.
  • Limits: each person’s game saves and patches have a 10 GB total for imports, and imports really can be as large as they say. Radio is limited to 4 streams a person and 32 a server. Pictures from game PCs can’t pile up, patched games are prepared one at a time, and a core is only asked what it offers one at a time, after its file is checked. Game PC stream limits now hold when several requests arrive together.
  • Accounts: deleting one removes its saves, patches, images and game PC identity, and ends its games and streams, so a new account can’t inherit them. Whoever started a game on a shared PC stops counting as its owner once it has ended.
  • Audit of game streaming, fixed:
    • A playlist in an archive that named itself crashed the server. Lists can’t name lists now.
    • The Linux sandbox had ways round it: x32 call numbers and io_uring reached the network and more, and a core could empty or change the mode of any file the server’s account could write.
    • Stopping could hang for ever on a runner that said it was ready twice, on one that left a child behind, or on one that had stopped reading. Stopping a game still starting could take the server’s slot with it.
    • A game still loading was stopped after a minute for having nobody watching, and that counted as a crash.
    • A resume state the core couldn’t load was overwritten when you left. It’s kept as the previous save now.
    • Starting another game while one loaded could bring the first back on another core. A core trying after another now gets its own graphics card access and memory limits, and its option list is kept under its name.
    • An encoder that died during a game froze the picture. Another starts now, and one that keeps dying is left out.
    • Holding rewind at the start of what’s kept ended the game without saving.
    • Refresh took a game’s lock off, and a rescan could replace a title typed by hand. Games on a gaming PC were looked up by the PC’s number for them, rather than by name.
    • An IPS patch writing the same place over and over could hold the server for minutes, and a file of unknown size could fill the disk past what’s left free. TheGamesDB’s names failed to load if a count came with them.
  • WittyCouch: a game’s name from a PC can no longer break out of the quotes in the Moonlight command people copy and paste, in PowerShell or a POSIX shell, and a name with an apostrophe now reaches Moonlight whole. The host program’s version check gets nothing of the server’s and runs in its sandbox, a program is only looked for in .build by development builds, and a viewer arriving just as a stream ends can’t leave a connection behind.
  • WittyMediaPlayer: a crashed disc helper can’t take the window with it, and dialogs closed while waiting on it are safe. Ripped tracks after the first start at zero. A long file whose video ends early no longer reads all its sound into memory. Closing with a drive stuck on a bad sector is safe and no longer waits on it, and a disc image never overwrites a file that appeared during the copy.
  • Fixed, from the audit of the web app: leaving a Game PC stream while it starts now ends it, and opening its menu no longer leaves keys held down on the PC. The visualizer’s flashing notice is each person’s own. Filters in a games library stay put during a scan or lookup. V no longer opens the visualizer over a game. A disc, and music after an audiobook, play at the right speed. Stations using HLS resume first time. Setting every keyboard button at once makes one profile. A refused cheat isn’t shown as added, and one Esc no longer loses an edited settings file. Games no longer put a sign-in in the WebSocket address over HTTPS.
  • Design audit: a page that can’t load now says so, with Try again, rather than looking empty. On narrower screens, Settings is a menu of its own with each item explained, and every page has a way back to it. The phone’s tab bar says where each button goes. Pages carry one legal note, at their foot. Gaming is now Consoles & cores, Games is My game settings, and the disc options moved from Transcoding to Playback & discs. There’s an Automatic theme that follows the device, the crash notice can be dismissed, and small controls are easier to tap.

Discs, audio and TV: what the audit found

  • Fixed: a panic during a Blu-ray title action could take the whole server down, and a button’s pause or resume never reached the player.
  • Encrypted media stays refused: a scrambled DVD title asked for directly and any action on an encrypted Blu-ray’s refusal screen now get the refusal. IPTV checks every HLS variant, and only calls a stream clear when all of them were read.
  • Encryption that starts later: an IPTV HLS stream’s playlists are read again while it plays or records. A key that appears stops the stream, marks the channel as encrypted and shows the usual refusal; a recording keeps what was clear and stops for the same reason, and a network failure ends nothing.
  • One wording: encrypted discs are refused in the same words everywhere a viewer sees them.
  • Crafted files: menu, subtitle and picture sizes are limited on every path, a helper’s answers are limited before decoding, a station can’t make the server build a huge playlist, and a CD sheet can’t leave its folder through a linked folder.
  • Older helpers: a WittyDVD helper from before chapter runs keeps the disc instead of being blamed, and a cut-short disc image no longer counts against an honest helper.
  • Fixed: a stopped stream’s clean-up could delete a new stream’s files, AIFF files are now checked to be CD audio, and a playlist from elsewhere can’t reach this machine by a name or a redirect.
  • Reset this server: Settings → Reset puts a server back as it was first installed, after warnings, your password and typing RESET. It keeps a copy you can bring back from the same page, unless you choose to delete everything. Media files are never touched. wms reset does the same when you can’t sign in.
  • Server 0.5.1-alpha: Everything from this round’s work together: games on every console, modules with repositories of their own, WittyCD, WittyCouch, WittyRigs, the visualizer, radio search, WittyLog, WittyDiagnoser and the Legal page.

Internet radio

  • Search a directory of stations: by name, genre, country or language, with logos and details, and add with one click. Stations come from Radio Browser, a free community database. Typing an address or importing a playlist still works.
  • Pages to match: station cards with logos, browsing by genre and country, favourites and recently played, and a page for each station with its details and website. Stations without a logo get art made from their name.
  • What’s on now: the song, from the stream’s own metadata, in the player and on lock screen and headphone controls.
  • HLS stations now play, and .pls and .m3u addresses are unwrapped when a station plays. Old servers that answer ICY 200 OK work.
  • Stations that go quiet are noticed and marked off the air, from playing them, from the directory, and from a check you can run. Checking in the background is a setting, off unless you turn it on, because it contacts stations when nobody is listening.
  • Pausing a station hangs up, so the server isn’t relaying it for nobody. A stream that drops reconnects by itself, and stations have a sleep timer.
  • For apps: /items/{id}/playback plays stations, and new routes under /radio (see CLIENT-API.md).
  • Fixed: listeners who weren’t administrators were sent each station’s address, which can hold a private key.

WittyPlay: make a game yours

Everything here is per person, can be set for all games, a console or one game, and is kept on the server, so it follows you. See GAMING.md.

  • The picture, drawn on your device: scanlines, CRT curve, phosphor pattern, glow, dark corners, an LCD grid, frame blend, sharp, pixel or smooth scaling, whole-number scale, shape (as the game says, 4:3, 16:9, square pixels, fill, custom), overscan crop, rotation, and colour, brightness, contrast and gamma. A colour or your own image around the picture, with presets to start from and a live preview. Effects cost the server nothing and add almost no delay. With no effect on, nothing at all sits between the video and the screen. Without WebGL, CSS does what it can. The one effect that flickers is off by default, says so, and stays off for anyone whose device asks for reduced motion.
  • On-screen numbers: frames shown and frames run, network delay, encode time, bitrate, drops, resolution, core and encoder, in the corner you choose. Off by default.
  • Speed: frame skip (automatic or fixed), fast-forward (hold or toggle), slow motion, pause and frame advance, rewind, run-ahead, and pausing when the tab is hidden. Fast-forward sends no more pictures than normal, so the encoder doesn’t pay for it. An administrator sets the fastest speed and rewind’s memory, and rewind and run-ahead back off or turn themselves off, saying so, on a machine that can’t spare the time.
  • Sound: volume, mute and a buffer size against crackling.
  • States: 99 slots with pictures and dates, quick save and load, undo a load, automatic save on exit, and a choice of resuming always, never or on offer. Starting over now keeps the old automatic save. States and battery saves can be downloaded and imported, with what comes in checked.
  • Screenshots and short clips, saved to your device.
  • Cheats, through the core’s cheat interface, typed in or from your own file. IPS and BPS patches of your own, applied to a copy when the game starts. Nothing is bundled.
  • Core options: every option a core really has, with its own names and descriptions, in its categories, in the menu and on the settings page, changing the running game. Options a core hides because they don’t apply stay out of the way.
  • Custom settings in JSON: edit, import, export and share a settings file, to set anything a core offers, and to define your own presets and controls: a toggle, slider or choice with your own label. Mistakes are shown at their line, with the list of what the core accepts beside them. Anything unknown is listed as ignored. A file can’t run anything, name files or reach the network, and imports are limited in size, depth and count.
  • Safe mode: start with defaults, from the game’s page or the error when a game won’t start, so that no setting can lock you out of a game.
  • Shortcuts: from the keyboard, from a controller by holding Select and pressing another button, and from on-screen buttons on a phone. All can be changed. The game menu holds everything above, and works with a controller, a TV remote and touch.
  • The game’s page: favourites, your own notes, play count, last played, and a resume banner with a picture. Administrators can set what everyone starts with.

More reliable

  • Games stay playable on a busy Windows server. The game runner used to run at below-normal priority, and Windows gives that next to nothing while other programs are busy: a game could fail with “took too long to load”, or crawl at one frame a second. It now runs at normal priority there, and shares the machine fairly with a transcode.
  • Save pictures and your own images load in apps that can’t send a sign-in cookie.
  • On Linux, the game runner’s limits hold on all of its threads. Writing outside the save folder could get past them from a thread other than the one that set them. A system that can’t cover every thread now says so in the log.

Lower delay

  • Games on the software encoder lost about a quarter of a second of delay on machines with many cores: it was holding back a frame for each of its threads. The new encode-time number showed it.

For client developers

  • API 1.4: game settings, cheats, patches, images, saved-file transfer and session numbers, listed in GAMING-API.md. Nothing about them lives only in the browser.

Add your own game cores

  • Custom cores for WittyPlay. An administrator can add a libretro core by uploading it, from a web address, or from the cores folder, and use it for a console, for one game, or as a console’s default, with other cores still available. See Adding your own core.
  • Tested before anyone can use it. Each file first loads in the same sandbox a game runs in, and what the core reports is shown: its name, version, file types, BIOS, graphics card and whether it’s built for this server. A crash or a hang only stops the test.
  • Safe by default. Off until an administrator turns it on, with the password each time. The SHA-256 is recorded, and a file that changes won’t run until someone looks at it. Web addresses are https and public only. Everything is in a history on the page.
  • Custom consoles, by form or JSON, for a core for a system our list doesn’t have. They appear when adding a library.
  • Timing calls for cores: the game runner now answers the libretro performance interface, which some cores refuse to start without.
  • Going back: earlier versions of a custom core are kept, and replacing or removing one never touches saves.
  • Which core works best: a game’s page shows administrators how each core has really gone on it.
  • Honest licensing: a custom core shows its licence if known, or “Unknown license”, with non-commercial ones labelled. They’re marked third-party and unverified, and this project never offers them.

WittyCD: audio CD images

  • CD images play in a CD player, a window in the spirit of the desktop players of the early 2000s, with the disc going in as DVDs do, a lit display, a list of tracks, and room on its stage for WittyVisualizer: .cue with .bin, .wav or a single .flac, .toc, .ccd, .nrg, .chd, and a bare .iso or .img that is really audio. In a Music library a disc is an album with its tracks; in a Discs library it sits on the shelf.
  • Gapless by design: the whole disc is sent as one stream, as lossless FLAC or WAV, with AAC for slow connections. Repeats, shuffle, your own program, index points, hidden tracks, pre-emphasis correction, and your place on the disc for each person.
  • Identified by table of contents through MusicBrainz and the Cover Art Archive, sending nothing else, with a dialog when several albums match. It can be turned off in Settings, Metadata agents.
  • Native apps get it through GET /cd/{id}, GET /cd/{id}/audio and the ordinary playback door: see Audio CDs in docs/CLIENT-API.md.
  • Tools: wms cd info, wms cd check and a standalone wittycd command. The module’s reader is a public library: track map, samples, disc ID and the lookup (wittycd/lookup), for WittyMediaPlayer and anyone else.

WittyVisualizer

  • Light shows that follow your music, in the audio player and in WittyMediaPlayer, from one set of shader files: spectrum bars, scopes, plasma, a tunnel, a starfield, feedback, a kaleidoscope, particles, fire, a wireframe landscape, a fractal and more. Seventeen effects written for this project, with beat-reactive colours, smooth transitions, random order, favourites and an automatic change of effect.
  • Press V or the bars button, on the whole screen, in place of the artwork in the full player, or small in the bar. Keyboard, remote and controller all work. Choices are saved per person on a server.
  • Safe by design: off until you turn it on, a notice before the first use, a calm mode that’s the default when the system asks for reduced motion, and a flash guard no effect can get around. It’s in the last step of drawing. A black and white strobe comes out as a dim steady glow.
  • Leaves playback alone: it listens to a copy of the sound where the browser allows, and on the desktop reads a lock-free copy. It runs only on your device, loads nothing until opened, adapts its resolution, and stops fully when hidden or off.
  • You can write your own, as a small text file, in the web app. It’s checked as untrusted and tried in a throwaway graphics context first.

WittyMediaPlayer

  • Plays and copies audio CDs, from a drive or an image, on a CD screen with a tracklist, a big now-playing area and a visualizer. Copies go to FLAC, ALAC, WAV, MP3, AAC, Opus or Ogg Vorbis, with naming templates, tags and cover art, and careful reads that retry, compare two passes, correct for the drive’s offset and report on every track. It can also make a .cue and .bin image of a disc. Names and covers come from MusicBrainz only when you press the button, which sends nothing but the disc’s track layout. Discs that won’t read normally get a plain message. The visuals are off until you turn them on, tell you about flashing light first, and go through a flash limiter.
  • A new desktop app, under apps/wittymediaplayer, that needs no server. It’s a first release for Windows amd64, as a portable folder, built with Qt 6 and FFmpeg’s libraries.
  • Plays ordinary video and audio files, with audio and subtitle track choice, seeking, volume, full screen, keyboard shortcuts, drag and drop, and subtitle files found beside a video.
  • Plays DVDs and Blu-rays with their real menus, by arrow keys, Enter and mouse, from images, folders and directly from a disc drive. It uses WittyDVD and WittyBluray with the same rules as the server’s player, without transcoding.
  • Makes .iso and .img images of discs for a server’s library. The copy is checked by opening it with the same engines the server uses, and it never overwrites anything.
  • Can play through the VLC libraries, by VideoLAN and the VLC contributors, chosen in Settings and loaded from a VLC already on the computer. They aren’t included. Disc menus still come from WittyDVD and WittyBluray.
  • WittyDVD and WittyBluray update on their own, without a new player, under the same rules as a server’s modules: a built-in copy that always works, signed releases only, version ranges, and going back by itself if a version keeps failing. Looking for updates is the only time the player uses the internet, and only when asked.
  • Refuses copy-protected discs, for playing and for copying, in plain words. It carries no decryption library, no key database and nothing that could load one, VLC’s disc modules aren’t used, and it never uses the network. See its design note.

WittyLog: logging that captures problems across everything

  • Every area has its own level, changed live with no restart: playback, transcoding, discs, games, Live TV, library, modules, updates, remote access, sign-ins, app errors, web requests and storage.
  • Every module has its own controls too. A level of its own and advanced options, such as a helper’s every call or a disc’s navigation. A module that is installed later is noticed and listed by itself. All of it is in Settings → WittyLog, and a module can list options of its own in its manifest.
  • Everything about one playback is tied together. One session links the request that started it, FFmpeg’s output, a disc’s or game’s steps, and what the player reported on your device. One press shows it all.
  • A viewer in Settings: live tail, filters by level, area, module, session and text, and common failures explained in plain words with a suggested fix. It works on a phone and with a TV remote.
  • Catch a problem: one button records everything for a while, then goes back to your usual settings by itself.
  • Crash reports. A fatal error, a caught panic, or a run that ended without shutting down (a power cut, say) leaves a report that survives, and the next start points it out. Each start also logs a summary: version, modules, system, graphics card and encoders, disk space and settings that matter.
  • FFmpeg, game runners and module helpers each leave how they ended, in words, with what they printed, bounded.
  • Failures that used to vanish are recorded: database errors, failed requests, scans, recordings, installs, updates, certificates, port mapping, sign-in lock-outs and background tasks that crash.
  • The apps report too. The web app sends uncaught errors, failed requests and player and game errors to your server. The desktop, Android and Apple apps keep a small log of their own and report crashes to your server.
  • One-click support bundle: recent logs, crash reports and a system summary as a zip, with a preview and a switch to hide titles and file paths. It’s downloaded by you, and nothing is uploaded anywhere.
  • It can’t get in the way. Logging never makes anything wait: when a disk is slow, full or gone, messages are dropped with a count and the server carries on. Files are limited by size and age. A quiet line costs about 40 ns and a written one about 3 µs.
  • Secrets are removed centrally, tested with secrets planted every way we could think of. Text from outside can’t forge a log line. The setup code is now only printed on the console, and not kept in the log files.
  • Failed requests are now recorded by default. So are app errors, which you can turn off.
  • How every part logs, for anyone adding code.

WittyDiagnoser: check discs and drives without a command line

  • Settings → WittyDiagnoser checks a disc: whether it’s encrypted (detected and explained, never bypassed), its structure, titles and menus, every menu button pressed with dead ends reported, Blu-ray and Java menu details, and damaged or unreadable sectors. The report it saves has nothing copyrighted in it.
  • It checks storage: free space, permissions, unreadable and missing files, read speed and whether that keeps up with a stream, network-drive and file-system quirks, and the drive’s own health where the system tells without administrator rights. Nothing is changed. The only thing written is a small temporary file, never in a media folder.
  • Long checks run in the background, one at a time, with progress and cancel, and give way to anyone watching. What it checks.

Legal notices

  • Short notices across the app say that web results and third-party content aren’t created by, associated with, endorsed by or checked by the project, and that a person’s own files and what they host are theirs. They come from one source, so every screen says the same thing, and apps get the words from GET /api/legal/notices. The connect screens of the WittyMediaClient apps show one too.
  • A Legal page in Settings, and at /legal for anyone: terms of use, no warranty, no affiliation, who’s responsible for what, trademarks, games and BIOS files, copy protection, flashing images, age ratings, and a privacy list of every outside service, what it receives and what controls it. About & legal is now About and Legal.
  • A server’s owner can add their own notice and contact details for the people using their server.
  • One tick in setup confirms that your files and what you share are your responsibility. Servers set up earlier show a one-time bar. The answer stays on your server.
  • Corrected: the README and setup said nothing leaves your home except titles. Update checks, other lookups and more do: the list is on the Legal page. Messages and docs about encrypted discs now just say they’re refused. Share links say they show your profile name. TheTVDB, Wikipedia on game pages, the dictionary service and podcast search now have their credits.
  • Removed from the README: older screenshots. Docs use made-up titles. Every module’s README has a Legal section. None of this is legal advice.
  • Privacy: live TV channel logos now load through the server, so the sites a playlist names never see a viewer’s address. Only internet addresses are fetched, never devices on the home network. As with other artwork, SVG logos are not served, so a channel with one shows no logo. WittyTuner 0.1.1 ignores a playlist logo that isn’t a web address.
  • Fixed: a Blu-ray playlist item that ends or starts part-way through its video could lose up to a second of picture at the join, show a little that should not be seen, or leave the sound short. Every item now plays exactly from its first frame to its last, with its sound, and an item that carries straight on from the last one is read as one recording. None of the discs tested here has such an item, and their main features play as before. This was checked with made-up discs built to have them.
